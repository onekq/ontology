Methodology

What's real here, what's fabricated, and why.

The companies are fake

Every "company" referenced in a vertical's materials/ folder — Cairn Drivetrain Co. in manufacturing, and whatever follows in later verticals — is fictional. No real enterprise's documents are used or referenced. Real internal documents are confidential and inconsistent in ways specific to that organization; publishing real ones wouldn't be possible or appropriate, so each vertical gets an invented company instead.

The mess is deliberate, not incidental

The fake source material isn't meant to be internally consistent. Each vertical's materials are written to contain the kinds of contradictions real enterprise documents actually have: departments using the same word for different things, supplier catalogs that cross-reference parts approximately rather than exactly, revision histories that don't supersede cleanly. The demo stages exist to show what it looks like to notice and resolve exactly this kind of mess — a tidy, conflict-free source document would make for a demo that teaches nothing.

The method is the reusable part

The Unfold method (Discover → Draft → Resolve → Validate) is the same across every vertical. What's specific per industry is which conflict shapes are common and what output format makes sense — see each vertical's recipe.md. This is deliberately not a single monolithic tool: it's a shared method with industry-specific guidance layered on top, so a vertical can diverge from the others' stage count or order without breaking the pattern.

Feedback

Each vertical page has a thumbs up/down and optional text feedback widget. Submissions are insert-only — there is no way to read feedback back through the public site or its API, only through the project owner's own dashboard access. See shared/core/feedback-widget.js if you want to verify that claim yourself.
