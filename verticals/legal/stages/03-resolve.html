Conflict 1 of 10
Parent decision — resolve first

Does "Ordinance 2019-14" mean the law, or its 2019 text specifically?

It's used both ways, and the ambiguity only matters once an amendment exists.

Recommended — Akoma Ntoso, used precisely
Model the ordinance as an FRBRWork, with each dated text version as its own FRBRExpression. A bare citation resolves to the current Expression by default; citing a specific date resolves to that Expression specifically. This is exactly what the FRBR layering in Akoma Ntoso is for.
Conflict 2 of 10

Clerk filing #, state citation, and code section are three separate reference schemes

None is cross-indexed against the others in one place.

Recommended — Akoma Ntoso
Keep all three as independent identifiers on the FRBRWork — none is more authoritative than the others for lookup purposes. Cross-index them explicitly rather than picking one as canonical and treating the others as derived.
Conflict 3 of 10 — highest stakes

2023-07's activeModifications was recorded; 2019-14's passiveModifications wasn't

Anyone looking up CLK-2019-014 directly has no signal that it's been amended.

Recommended — Akoma Ntoso, used as intended
Assert passiveModifications on CLK-2019-014 pointing back to CLK-2023-007 — the spec's bidirectional design exists precisely so a gap like this is structurally visible. Beyond fixing this one instance, add a domain integrity check: any Work with an activeModifications pointing at a target should require that target to carry a matching passiveModifications, flagged when it doesn't.
Conflict 4 of 10

TMC 9.04.010 was repealed but never given an @end date

It still displays as in force in the codified text.

Recommended — Akoma Ntoso, precise rule
Assert @end on TMC 9.04.010's Expression at the 2021 repeal date, per the spec's own rule: an @end with no @start marks a repealed original fragment. Add a domain check flagging any Expression referenced by a repealing ordinance's activeModifications that lacks a corresponding @end.
Conflict 5 of 10

The posted PDF doesn't reflect the current Expression

Last regenerated 2022; the 2023-07 amendment isn't in it.

Recommended — Akoma Ntoso
Give the FRBRManifestation its own lastGenerated date (domain), and flag manifestationStale: true whenever that date precedes the Expression's most recent amendment date. The canonical Expression is correct; the Manifestation just hasn't caught up, and that gap should be queryable rather than discovered by a citizen reading outdated law.
Conflict 6 of 10

"Code" and "Section" mean different things to different offices

Clerk: the whole consolidated Code / a Municipal Code division. Enforcement/Records: one cited section / an unrelated filing-folder tab.

Recommended — Akoma Ntoso + domain
The Clerk's "Code" is a domain CodifiedCode aggregate over all current FRBRExpressions; Enforcement's is a single FRBRWork/section — both legitimate, already distinguishable once Conflict 1 is resolved. The Records Office's "Section" (a filing-folder tab) gets its own domain FilingDivision class, unrelated to the Municipal Code's real hierarchical section element — same "two real, unrelated concepts sharing a word" pattern as prior verticals' pure naming collisions.
Conflict 7 of 10

A cross-reference still uses pre-recodification numbering

TMC 14.20.030 cites "Section 14.08.010," which no longer exists under that number.

Recommended — Akoma Ntoso
ref elements should target a stable, location-independent identifier per Akoma Ntoso's own naming convention — not a citation number that recodification can change out from under it. Flag any ref whose target citation predates the most recent recodification event as needing revalidation, rather than trusting old references to have survived unchanged.
Conflict 8 of 10

"Enacted date" conflates three legally distinct dates

Passed, published, and legally effective dates can differ under state law's waiting-period rules.

Recommended — Akoma Ntoso
Record all three as distinct lifecycle/temporalData events rather than one flat "enacted_date" field — the spec's event-based model already accommodates this; the registry's single field was just a simplification that lost real, legally meaningful distinctions.
Conflict 9 of 10

The records-request checkpoint doesn't verify currency

"Confirm document provided" passes whether the pulled document is current or superseded.

Recommended — domain-specific
Add a domain verifiedCurrentExpression: false flag on this checkpoint — same cross-domain checkpoint-gap pattern as every prior vertical. A checkpoint named "confirm provided" doesn't imply "confirm current" unless it actually checks that.
Conflict 10 of 10

The published SLA doesn't match actual code-section request turnaround

Published: 10 business days. Actual for code-section requests: 18 days average.

Recommended — domain-specific
Model two domain RequestSLA instances — the published standard and the actual figure for code-section requests specifically — rather than reconciled into one number, same principle as every prior vertical's operational-disagreement conflict.
