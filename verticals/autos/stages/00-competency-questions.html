Stage 0 — Scope

Before reading a single source document, write the questions the finished ontology needs to be able to answer — competency questions (Grüninger & Fox 1995, popularized by Noy & McGuinness). This is the field's actual standard first move. Skipping it is how an ontology ends up internally tidy but unable to answer the question anyone actually needed answered.

Overland Autonomy's competency questions

Written before Discover, checked again in Stage 4 — Validate. Status shows whether the current ontology can answer it, not whether it's a good question.

Is a given vehicle's automation level for a specific trip "true driverless," or supervised — independent of the platform's marketed maximum level? Answerable
Which VIN does a given fleet ID actually denote at a given point in time? Answerable
Is a specific road segment inside a vehicle's actually-validated ODD, regardless of what the marketing service-area map shows? Answerable
What caused a specific disengagement, and whose determination is authoritative for regulatory reporting? Answerable
Do two differently-labeled release identifiers in Fleet Ops and Engineering's systems refer to the same deployed software build? Answerable
Did a given software release change a value a safety requirement depends on, and if so, was that requirement re-verified? Answerable
What is the currently valid ASIL rating for a given subsystem, and does it match the rating used in the original hazard analysis? Answerable
Does the ODD register's validated max speed for a road class agree with Perception Engineering's own detection-envelope spec for that class? Answerable
Was a given completed trip's actual route fully within its jurisdiction's permitted boundary? Gap
Was a safety driver actually present for a given trip, as distinct from merely scheduled or required by policy default? Gap

What the two gaps mean

Everything answerable above came from the fleet registry, incident log, ODD register, release log, and safety-case requirements — all fleet/engineering-shaped source material. Neither gap can be closed by that material, because neither is about what the fleet or software is — they're about what's legally authorized and what actually happened on a given trip, which only the permit conditions and vehicle telemetry can answer together. That's not a coincidence: it's why materials/06-regulatory-permit-register exists. Stage 1 picks up from here.
